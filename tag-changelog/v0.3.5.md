kanbrain leaves nothing behind in the user's cache: purging a brain or uninstalling with purge clears its write
locks and migration backups, and a brain in the temporary folder keeps them there.

- Cache (`core/src/store.rs`): `cache_dir_of` puts a brain under `/tmp` (on Unix, whatever `TMPDIR` says, so every
  process agrees on its lock) or under the temporary folder in `<tmp>/kanbrain-cache/<kind>/<key>`, else in the
  user's cache as before (`<cache>/kanbrain/<kind>/<key>`). `store::cache_of` names a brain's lock file and backups.
- Purging a repository (`cli::manage::remove_repo` with `purge`: `kb deinit --purge`, `kb project remove --purge`,
  the app's Remove…) deletes them after its `.brain/`, best effort (Windows can't delete a lock held open).
- Installers: `install.sh --purge` and `install.ps1` with `KANBRAIN_PURGE` delete `locks/` and `backups/` in
  kanbrain's cache folder (`${XDG_CACHE_HOME:-~/.cache}/kanbrain`, `~/Library/Caches/kanbrain`,
  `%LOCALAPPDATA%\kanbrain`), and the folder once empty. `e2e/install.sh` and `e2e/install.ps1` now purge too:
  the data and the cache go, a file kanbrain didn't create stays.
- Tests no longer write into the developer's cache folder: their brains are in the temporary folder.
