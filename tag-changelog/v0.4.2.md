An agent writing a brain's files itself is now refused by a Claude Code hook and sent to `kb`. The kanban app takes
the lock of a brain it finds while it acts, scrolls a one-line field to keep the cursor in view, takes `f` on the
board only, and highlights the tags list after a paste or cut. CI runs each job only for what a change touches. Not
breaking: `kanbrain-core` gains `BrainLock::taken`, nothing else of its API changes.

- Agents (`core/src/cli/`):
  - `init` adds a fourth Claude Code hook (`claude::HOOKS`): `PreToolUse` on `Edit|Write|MultiEdit`, running
    `kb hook edit`. `kb update` adds it to every project (`init --all`); `deinit` takes it out.
  - `kb hook edit` (`hook::refuse_brain_write`): a file in a project's `.brain/`, or kanbrain's own in the central
    brain (`hook::central_owned`: a file at its top, as `Store::load` reads every `.md` there, `last-id`, `format`,
    anything in `projects/` or `reports/`; not a notes vault's other files, nor a repository kept there), also
    through a link (`hook::real_path`, by the nearest folder that exists), gets `permissionDecision: deny` and a
    reason telling the agent to make the change with `kb`, or tell the user what to change; anything else, nothing.
    A shell command's writes aren't seen.
  - `init`'s message, `kb --help`, `docs/agents.md` (four hooks; a merge conflict in a committed `.brain/` is the
    user's), `docs/cli.md` and the README say so; the README no longer says the `Stop` hook holds the turn.
- Kanban app (`gui/`):
  - `View::locked`, after catching up: `Board::lock_found_brains` takes the lock of each brain the thread doesn't
    hold yet (a project registered meanwhile) and, with any taken, reads every brain again under the locks.
    `BrainLock::taken` (core): whether a guard took the lock rather than finding the thread held it.
  - One-line fields (`widgets::text_field`): sideways scroll (`overflow_x_scroll`), one `ScrollHandle` per
    `TextBox` (`FieldScrolls`); `caret::keep_in_view` scrolls as little as needed for the cursor to show inside the
    8-pixel padding (`INSET`), under 0.5 px (`SLACK`) not at all, and asks for a frame of its own (`on_next_frame`).
    A field not typed into shows its start.
  - `f` is `Tabs::Board` (it ran on the notes and decisions too, changing the board unseen); `When::OnBoard` is gone.
  - `Board::paste` and `Board::cut` recompute the form's tags highlight (`Board::retag`, `Board::tag_highlight`,
    shared with typing).
- CI (`.github/`): `plan.sh`, a first job of `ci.yml` and `mutants.yml`, runs each job only when the change touches
  what it checks (files built into the programs count as their code), everything on `release/*` or a change to the
  workflows, `Cargo.toml`, `Cargo.lock` or the toolchain, mutation testing only for Rust lines, and nothing for a
  tree a passing run already checked (artifact `<workflow>-tree-<tree>`, 90 days). `docs/development.md` has the
  table; pull requests are squashed into `develop`, releases into `main`, then `main` is merged back. A tree's
  artifact counts only from a run of this repository; a pull request is measured from the last commit of its base
  a push run passed (none: every job runs); `git diff --no-renames` sees both sides of a rename; the README counts
  as `kb`'s code (a test checks it lists the same commands).
- Tests: `e2e/agent.sh` gains an `edit` scenario: the section removed, an agent told to edit a task's file is
  refused by the hook and runs `kb done`. `gui/tests/ui.rs`'s `next_frames` fails a test whose window still asks
  for frames after 10, as it said it did.
