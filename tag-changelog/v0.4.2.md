An agent writing a brain's files itself is now refused by a Claude Code hook and sent to `kb`. The kanban app takes
the lock of a brain it finds while it acts, scrolls a one-line field to keep the cursor in view, takes `f` on the
board only, and keeps the tags list's highlight on its tag after a paste, a cut or a reload. CI runs each job only
for what a change touches. Not breaking: `kanbrain-core`'s API doesn't change.

- Agents (`core/src/cli/`):
  - `init` adds a fourth Claude Code hook (`claude::HOOKS`): `PreToolUse` on `Edit|Write|MultiEdit`, running
    `kb hook edit`. `kb update` adds it to every project (`init --all`); `deinit` takes it out.
  - `kb hook edit` (`hook::refuse_brain_write`): a file in a project's `.brain/`, or kanbrain's own in the central
    brain (`hook::central_owned`: `tags.md`, `projects.md`, `last-id`, `format`, anything in `projects/` or
    `reports/`, and an entry at its top: named as one, `store::entry_named`, or a file `Task::from_markdown` reads
    as one or fails on other than `model::MISSING_ID`, as `Store::load` and `say_skipped` do; only a regular file is
    read; not a notes vault's other notes, nor a repository kept there), also through a link (`hook::real_path`, by
    the nearest folder that exists), gets `permissionDecision: deny` and a reason telling the agent to make the
    change with `kb`, or tell the user what to change; anything else, nothing. The path is taken as Claude Code
    takes it (`hook::written`): a leading `~` is the home folder, a relative one is in the session's `cwd`, `..` is
    resolved as text (`hook::lexical`). A shell command's writes aren't seen.
  - `api::json`'s `path` says a change goes through `kb`, not the file.
  - `init`'s message, `kb --help`, `docs/agents.md` (four hooks; a merge conflict in a committed `.brain/` is the
    user's), `docs/cli.md` and the README say so; the README no longer says the `Stop` hook holds the turn.
- Kanban app (`gui/`):
  - `BrainView::locked`, after catching up: `Board::lock_found_brains` takes the lock of each brain not tried yet in
    the input (`tried`: a project registered meanwhile) and, with any taken, reads every brain again under the locks.
    Each brain's lock is tried once an input: one that failed isn't taken later in it, after a repository's.
  - One-line fields (`widgets::text_field`): sideways scroll (`overflow_x_scroll`, a wheel left to what holds the
    field: `restrict_scroll_to_axis`), one `ScrollHandle` per `TextBox` (`FieldScrolls`); `caret::keep_in_view`
    scrolls as little as needed for the cursor to show inside the 8-pixel padding (`INSET`), no further than the
    field scrolls (`ScrollHandle::max_offset`), by 0.5 px (`SLACK`) or less not at all, and asks for a frame of its
    own (`on_next_frame`). A field not typed into shows its start.
  - `f` is `Tabs::Board` (it ran on the notes and decisions too, changing the board unseen); `When::OnBoard` is gone.
  - `Board::paste` and `Board::cut` recompute the form's tags highlight (`Board::retag`, `Board::tag_highlight`,
    shared with typing). `Form::tag_sel` is the highlighted tag (`Option<String>`), not its row: a reload adding a
    tag ahead of it moved the highlight onto another; one the reload took out is highlighted no more. A click puts
    the tag clicked (`Board::choose_form_tag(&str)`), not the row's after catching up.
- CI (`.github/`): `plan.sh`, a first job of `ci.yml` and `mutants.yml`, runs each job only when the change touches
  what it checks, everything on `release/*` or a change to the workflows, `plan.sh`, `Cargo.toml`, `Cargo.lock`, the
  toolchain, `.cargo/`, `rustfmt.toml` or `deny.toml`, mutation testing only for Rust lines, and nothing for a tree a
  passing run of this repository already checked (artifact `<workflow>-tree-<tree>`, 90 days). A change is measured
  from the last commit of the branch, or of a pull request's base, whose push run passed (none: a push from the push
  before it, a pull request runs every job), both sides of a rename seen (`--no-renames`). Files built into a program
  or read by its tests count as its code: the README `kb`'s, `install.sh` and the logo the app's, the fonts' licenses
  `xtask`'s; a crate's `Cargo.toml` runs the licenses too, `gui/icons/` the installers. `docs/development.md` has the
  table. `release.yml` asks for the release squashed into `main`, then tagged.
- Tests: `e2e/agent.sh` gains an `edit` scenario: the section removed, an agent told to edit a task's file is
  refused by the hook and runs `kb done`; `claude` gets no stdin (it waited 3 s for it). The app's smoke tests clear
  every agent variable `kb` reads. `gui/tests/ui.rs`'s `next_frames` fails a test whose window still asks for frames
  after 10, as it said it did. `.cargo/mutants.toml` leaves out `caret::keep_in_view`'s edge comparisons and the
  editor's cursor row (`dialogs/editor.rs:56`); its tags-list exclusion names its line (`dialogs/form.rs:168`), so
  the row the list follows is mutated (`the_forms_tags_list_follows_its_highlight`).
