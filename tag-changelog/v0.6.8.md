The kanban app and `kb` at 10,000 entries: only the rows in view are drawn, the board's derived state is kept per
change, the disk is watched off the window's thread, and `kb` reads a brain side by side and one entry's file alone.
No data format change: nothing to migrate. Decisions 0008–0013 in `docs/decisions/`.

- Kanban app (`gui/`):
  - `ui::offscreen` (`Rows`): the board's columns, the list layout and the notes and decisions lists draw the rows of a
    view above and two below the one shown, with one box per run of the others, of their height. Heights are kept
    once laid out and dropped when the rows' width changes; rows never laid out take the mean of those that were. A row
    above the view never laid out is laid out first out of sight (`Frame::finish`: an absolute, hidden box where the
    rows start, the list's last child) and drawn the next frame. The scroll stays anchored to the first drawn row that
    shows (`Rows::learn`, `keep_view`); a list at its end stays there. A list first shown on the row it follows sets
    the scroll itself, then follows it again the next frame, once (`Rows::refollow`).
  - `state::index`: per brain, the entries by id, each column in order with its count, related entries (in another repository's order: source, then
    note, decision, task, newest first), tags in use by kind, the tasks waiting for an answer, kept by `Source`'s revision; `Showing` holds what the scope and search
    show. `Source::brain` is private, so every change goes through `brain_mut`.
  - `ui::board`: a card (`draw_card`) and a column's body (`column`) lay out as blocks, spaced by margins; the boxes
    standing in take the gap learned from the layout.
  - `ui::dropdown::list`: every picker, the form's project, tags and related fields, Manage project, + Add project,
    the command palette and the dropdowns draw the rows from a view above to two below, each `ROW_HEIGHT` (28 px) tall,
    and scroll by the rows' heights (`followed`, `hidden`), so a list opened far down shows its rows on the first
    frame. `state::form::form_tags` counts tags from the index.
  - `watch::Watcher`: the folders are listed on GPUI's background executor every `INTERVAL` (1 s); a key or the
    board's own write skips a folder whose time is unchanged, unless it changed within `TICK` (2 s, on a file system
    keeping times to the second or two) or `FINE_TICK` (50 ms), where a listing can't be trusted to hold. `Watcher::sync` takes as seen only the files as the board's stores read or wrote them.
  - `state` (`Board::reload_changed`): reads again only the files that changed (`Brain::reload_files`), every brain
    even when one fails.
- Core (`core/`):
  - `Brain::reload_files(&[PathBuf])`: reads only those files again, each once by its name in the brain's folder,
    then repairs as a full read; any file other than
    an entry's reads the whole brain.
  - `Store::save` refuses to write over a file changed or deleted since the store read or wrote it, by its time and
    length (`Store::known`).
  - `Store::load_entries` reads on up to four threads (`READ_THREADS`), shares of at least `READ_PER_THREAD` (512),
    the calling thread for a share no thread can be had for; each file opened once, its time and length taken from
    the open file.
  - `Store::load_named(id)` and `Brain::open_for`: `comment`, `ask`, `describe`, a status other than doing and
    `wait`, said as a line (`EntryArgs::alone`), read only the files named `{id:04}-`, when one reads and holds that
    id; otherwise the whole brain, repaired. `wait` polls that file (`read_for`).
- Benchmarks: `gui/tests/perf.rs` and `perf_commands_over_ten_thousand_entries` in `cli/tests/kb.rs`, ignored by
  default (`docs/development.md`, Performance).
- Dependencies: pulldown-cmark 0.13.5 (RUSTSEC-2026-0414).
