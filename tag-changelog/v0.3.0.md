Projects are managed from the kanban app and `kb project`: rename a project or a repository, move a repository to
another project, remove a repository or a whole project keeping or deleting its tasks. Two folders with the same name
can now join one project. Breaking: `kanbrain-core`'s `cli::init`, `projects::read_repo_card` and
`projects::write_repo_card` changed.

- Repository names (`core/src/projects.rs`): `Repo::name` is the `- repo:` line under the title of its
  `.brain/project.md` (`RepoCard { project, repo, notes }`), else its folder (`Repo::folder`). `projects::repo_name`
  picks it on `init`: `--repo REPO` (refused when the project has it; `check_repo_name`: one word, no `,` `#` `:`
  `/`), else the card's, else the folder's, else `<folder above>-<folder>`, else `<folder>-N`. `kb init [NAME]
  [--repo REPO]`; `cli::init(root, name, repo, central)`.
- Management (`core/src/cli/manage.rs`): `rename_project` (registry, card via `projects::rename`, each repository's
  card), `rename_repo` (card, and the siblings' `REPO#ID` links rewritten under their locks), `move_repo` (links to
  the old project's repositories dropped on both sides, then `init`), `remove_repo` / `remove_project` (siblings'
  links dropped, `deinit`, `.brain/` deleted with `purge`, only a folder named `.brain`). CLI: `kb project rename
  NAME…`, `repo NAME`, `move PROJECT…`, `remove [--purge]` (`ProjectChange`), `kb deinit [--purge]`.
- `Store::lock` is re-entrant per thread (`HELD`): taking a lock the thread holds returns a guard that does nothing,
  so the app, which holds every brain's lock while it acts, can run management that takes some itself.
- Kanban app: **Project info** (`I`) has Rename… (project, each repository), Move…, Remove… (`Mode::Manage`,
  `gui/src/state/manage.rs`, `gui/src/ui/dialogs/manage.rs`; Unlink `y`, Unlink and delete tasks `d`), **+ Add
  repository** (`Request::Folder(Some(project))`) and **Remove project…**.
