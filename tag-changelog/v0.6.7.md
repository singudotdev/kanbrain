The kanban app's project filter shows several projects at once, as the tag filter shows several tags. No data format
change: nothing to migrate.

- Kanban app (`gui/`):
  - `state::sources`: `Board::scope` is a `Vec<Scope>` of picks, every brain shown with none. `Board::toggle_scope`
    adds a pick or takes it out; `Scope::All` takes every one out; a project and its own repositories take each
    other's place. `Board::shown_alone` is the one project or repository picked alone; `Board::project_src`,
    `repo_here` and `title` act on it, so the project card, Manage project and the window's title need one.
    `Board::scope_checked` checks the dropdown's rows; `choose_scope` keeps the dropdown open, as `choose_tag` does.
  - `state::reload`: each pick follows its folder or project (renamed, moved: under its new name; gone: dropped, the
    others kept); a repository picked that's now in a project picked, or its project's only one, is that project.
  - `state::manage` (`apply_manage`): a repository shown that a rename or move takes out of the picks adds its
    project to them, keeping the others.
  - `ui::topbar`: the button names what's shown, `Project: All`, `Project: shop`, `Projects: shop, blog`; the
    command palette's `P` is "Filter by projects".
- Docs: `docs/tasks-and-tags.md` (several projects shown), `docs/keybindings.md` (`P`, `I`, `E`, the dropdown's
  clicks).
