The kanban app links a bare URL and each reference of a slash-listed `#1/#2/api#3`; the agent section `kb init` writes
asks agents to cite pages, pull requests and CI runs as markdown links and to name several entries apart. No data
format change: nothing to migrate.

- `kanbrain-core` / `kb`:
  - `cli::init` (`SECTION`): the links bullet asks for the markdown link, `[PR #39](URL)`, not just `PR #39` or the
    bare URL, and names several entries apart (`#1, #2 and web#3`), never joined by `/`; the official-documentation
    bullet links the page with a markdown link, `[serde: field attributes](URL)`, not a bare URL. `init --all`, run
    by the installers and `kb update`, rewrites it in every registered repository.
- Kanban app (`gui/`):
  - `ui::markdown`: `urls` finds GFM extended autolinks in prose (`http://` or `https://` at a word's start or after
    `*`, `_`, `~`, `(`; a domain of two or more parts, no `_` in the last two; up to whitespace or `<`, less trailing
    `?!.,:*_~`, an unmatched `)` and an `&name;` entity), which pulldown-cmark 0.13 doesn't; `Builder::prose` draws
    them and the references as links in order, skipping overlaps. `references` lets one after `/` through right after
    the one before (`#1/#2`); a listed one follows the words its list's first one does, so `PR #38/#39` stays numbers.
- Tests: `e2e/agent.sh`: `links` requires the markdown link; `implement` fails on a bare URL to a domain outside code,
  links and reference definitions; `full` also accepts the agent's task parked asking the user (the rule since 0.6.4).
- Docs: `docs/agents.md` (the section, word for word), `docs/tasks-and-tags.md` (bare URLs, slash lists),
  `docs/development.md`.
