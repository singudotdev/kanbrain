The kanban app is built on GPUI from Zed 1.29.2 (it was 1.23.2). `kb` and kanbrain-core are unchanged but for the
version. No data format change: nothing to migrate.

- Kanban app (`gui/`):
  - `gpui` and `gpui_platform` from Zed tag `v1.29.2`; `[patch.crates-io]` as Zed builds them: `async-task` from
    `zed-industries/async-task` (`015845a`), `calloop` `3759371`. Text wraps at UAX #14 line breaks.
  - `ui::application`: on Linux `gpui_platform::linux(windowing())`, `windowing` being `WindowingModes::all()` but
    `HEADLESS`: GPUI never starts headless.
  - `ui::launch`/`connecting`: making the app and its `run` under `catch_unwind`; a panic before the `run` closure
    sets its flag is the window system's (`couldn't connect to the window system: …`, exit 1), one after unwinds on.
  - `display::ensure_display_on` matches `"headless"`, GPUI 1.29's `guess_compositor` with no display.
  - `scrollbar`: `ScrollWheelEvent` is `ScrollEvent`.
- Dependencies: `Cargo.lock` at the latest compatible versions; `deny.toml` drops the `paste` advisory
  (RUSTSEC-2024-0436, no longer in the tree) and allows the `gfx-rs/wgpu` and `zed-industries/oo7` git sources.
- CI: every workflow action pinned by commit SHA; Dependabot opens its pull requests against `develop`.
- Docs: `docs/decisions/0016-the-app-never-runs-headless-and-says-a-failed-connection.md`; `docs/development.md`.
