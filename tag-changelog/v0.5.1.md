The kanban app no longer replaces unseen what `kb` writes while its form or editor is open: a save over a change made
meanwhile stops and says so, an open dialog is marked `· changed on disk` the moment `kb` changes what it edits, and
opening one on a task an agent is working on says so. A verdict being written isn't turned over a decision `kb`
decided meanwhile. Agents are told to link the pull requests, issues and pages they name. No API, command line or
data change: nothing needs migrating; `kb update` brings the new agents' section to every project.

- Kanban app (`gui/`):
  - Editor save over `kb`'s change (`Board::save_edit`): `Edit::base` is the text the editor opened on, or that a save
    that stopped found; another text on disk stops the save, the editor left open (`… changed meanwhile: save again
    to replace it with yours, ctrl+d to keep it`). `Edit::comments` keeps the entry's comments as opened:
    `Board::same_comment` stops for good a comment save when another was put at its index (`… comments changed around
    this one meanwhile: copy your text, then ctrl+d`). The comment editor's title names the comment it opened.
  - Form save over `kb`'s change (`Board::submit_form`): a title both changed stops it (`… title changed meanwhile,
    to “…”: save again to replace it`; `Opened::title` moves to it).
  - Verdicts (`Edit::decision`): the reject and accept-with-a-comment editor stops when the decision's state differs
    from where it stood when it opened or at the last stop (`#N was accepted meanwhile: save again to reject it
    anyway, ctrl+d to leave it`; proposed again, the same); the same verdict as the one written stops for good
    (`… copy your reason, then ctrl+d`), since `Brain::resolve` would drop the text.
  - `· changed on disk` (`Board::mark_changed_on_disk`, `edit_changed_on_disk`, `form_changed_on_disk`,
    `Edit::changed_on_disk`, `Form::changed_on_disk`, `dialogs::titled`, `editor::title`): set by `Board::after_load`
    once `kb` changes the form's title, tags, related entries (as a set) or status, or the editor's text, the comment
    at its index (by time and author), the task's status or the verdict; kept until closed, said once in the status
    bar (`#1's title and status changed on disk`). New comments and other comments edited don't count. The editor's
    unsaved dot stays last (`Description · changed on disk •`).
  - Messages a read finds (`Board::notify_found`, `Board::say`, the `found` flag of `Board::message`): the mark, a
    file skipped, a dialog closed as gone; the message of the key that read for goes before it (`#1 saved · #1's
    status changed on disk`) instead of replacing it.
  - `Board::say_agent_working`: opening the edit form (`edit_selected`), the description or a comment
    (`open_editor_from`) of a task in doing that an agent started (`Task::started_by`) says `#N is being worked on by
    an agent`; a new comment doesn't.
  - `closed: shop/api #1 is gone, deleted or moved meanwhile`: a dialog closed because its entry left the brain is
    named with `Board::entry_name`, and a `kb move` isn't called a delete.
- Agents' section (`init::SECTION`, `docs/agents.md`): a pull request, issue, CI run, commit or page named in a comment
  or body goes with its link, `[PR #39](URL)`, not just `PR #39`.
- Tests: `gui/tests/state.rs` saves the editor, form and verdict over `kb`'s changes, marks open dialogs and warns on
  an agent's task; `gui/tests/dialogs.rs` the marked titles; `cli/tests/kb.rs`'s `tempdir()` refuses a `TMPDIR`
  with a `.brain` above it, through a link too, before `kb` runs; `e2e/agent.sh links`, and its checks read boards
  whose tasks have no comments.
