Entries say who changed their title, tags, related entries or description, and when: each change is logged in a new
`## Activity` section of the entry's file, and the kanban app and `kb show` list it among the comments, like an
issue's thread. `kb tag OLD NEW` renames a tag in every entry. Breaking for `kanbrain-core`'s Rust API only (`Task`
has a field); `kb`, the app and the data need nothing migrated: the format stays 1, a file without the section reads
as one with nothing logged, and every released version keeps a section it doesn't know (ADR 3). `e2e/update.sh` runs
every released `kb update` against this build before it's released.

- Model (`core/src/model/mod.rs`, `markdown.rs`):
  - `Task::activity: Vec<Activity>` (`at`, `by: Author`, `change: Changed`); `Changed::{Title { from, to }, Tags {
    added, removed }, Related { added, removed }, Description}`, `Changed::said`. Written as `## Activity` after
    `## Comments`, only once there's an item: `- <time> <what>`, `(agent)` for an agent's, a title's old and new value
    on lines of their own, tags and related entries as `+added -removed` (`+5 -shop-api#3`), a description as
    `changed`.
  - An item this version can't read is kept as written (`Unknown::activity`), and so is text in the section before
    the first item.
  - `Task::log` keeps items in time order and merges a change into the latest item only when it has the same time
    (to the second), author and kind; one that ends up changing nothing is removed. `Task::set_title`, `set_tags`,
    `set_description` and `relate` change and log; `Task::thread` interleaves comments and changes
    (`ThreadItem::{Comment, Change}`), a change first within its second.
  - `#[non_exhaustive]`: `Task`, `Comment`, `StatusChange`, `Session`, `Unknown`, `Activity`, `Changed` (not its
    variants), `api::ApiError` and the JSON shapes in `api::json`. `Kind`, `Status`, `DecisionState`,
    `period::Unit` and `brain::Group` stay exhaustive.
- Logged (`core/src/brain/actions.rs`, `api/mod.rs`): `Brain::update`, `set_description`, `toggle_link` and `link`
  (on both entries; `link` saves the entry that keeps the links first), `toggle_repo_link` and `link` to another
  repository (only the entry whose `- links:` line changes), `rename_tag`. Deleting or moving an entry, and loading
  dropping links to a missing one, log nothing.
- CLI (`core/src/cli/entries.rs`, `api/text.rs`, `api/json.rs`):
  - `kb tag OLD NEW` (`EntryCommand::RenameTag`, `Brain::rename_tag`, `TagColors::rename`): renames the tag in every
    entry that has it (the new tag takes the old one's color unless it has one) and prints each renamed entry
    (`--json`: their summaries); `ApiError::NoTag` when none has it. A numeric `OLD` that is an entry's id is
    refused unless written `#5`.
  - `kb show`: the section is `Comments`, `Changes` or `Comments and changes`, with the latest 10 changes
    (`CHANGES_LIMIT`; `(latest 10 of N changes)`); `--json` gives every one in `activity` (`EntryChange`: `at`,
    `author`, `changed`, `from`, `to`, `added`, `removed`; related entries as strings, `"5"`, `"web#1"`).
- Kanban app (`gui/src/ui/drawer.rs`): the details' thread lists comment cards and a line for each change, by time
  (`change_line`, `change_label`): `An agent changed the title from "Fix login" to "Fix login 500"`, `You added the
  tag #prod`.
- Docs: `docs/data-format.md`, `docs/tasks-and-tags.md`, `docs/agents.md`, `docs/faq.md`, `docs/development.md`,
  both READMEs, ADR `docs/decisions/0003-entries-log-their-changes-in-an-activity-section.md`.
- Tests: `core/tests/model.rs`, `model/markdown.rs`, `brain.rs`, `api.rs`, `cli/entries.rs`, `gui/tests/ui.rs`;
  `e2e/upgrade.sh` checks that each released `kb` keeps this build's `## Activity`; `e2e/update.sh` (new, CI's
  upgrade job): each release's `kb update`, with a stand-in `curl` serving this tree's `install.sh` and build as the
  latest release, installs it, and this build reads its brains and leaves `init --all` with nothing to change.
