kanbrain no longer loses or misses a write when `kb`, agents and the kanban app run at once, never recreates a
deleted repository's brain, and updates from the latest release's installer. The kanban app embeds its fonts, has a
key for every button, and redraws only when something on it changes; the command line's errors and lists say more
with less.

- Locks (`core/src/store.rs`, `core/src/projects.rs`, `core/src/cli/mod.rs`):
  - `projects::register`, `unregister` and `rename` hold the central brain's lock from reading `projects.md` to
    writing it: `kb init`s run at once all keep their repository.
  - `run_entries` takes the central brain's lock before the repository's for `kb project rename|repo|move|remove|
    describe|notes`, in the order the app takes them: the two could each hold one and wait for the other.
  - `kb wait` and `kb report` open the brain under its lock, as opening may repair files; `wait` lets go once open.
  - `EntryArgs::read_stdin` reads a `-` argument before the lock, so a command waiting for its input holds up no
    other `kb` nor the app.
  - `Store::lock` records a lock in `HELD` only once taking it can't fail: an error left the thread's later locks
    holding nothing.
- Writes (`store::write_file`): to `.NAME.PID-N.tmp`, a name of the write's own, flushed with `sync_all` before the
  rename. `Store::lock` deletes such files over an hour old in the brain and its folders (`forget_cut_writes`), left
  by a crash.
- A deleted repository stays deleted: `Store::open_named` (`--project`) fails with `… is gone: kb --project NAME
  deinit takes it out`, and `kb update`'s look for agents at work (`update::agents_working`) skips a registered
  folder that's gone, instead of creating its `.brain/`.
- `kb status` (`status_line`) leaves out a brain it can't read (one a newer kanbrain wrote) instead of failing.
- `migrate::format_of` refuses a `format` file saying `0` instead of panicking.
- Temporary brains (`forget_gone_temp_brains`): each lock file in `<tmp>/kanbrain-cache/locks/` names its brain on
  its first line; once that brain is gone, its lock and backups are deleted as another is locked.
- Kanban app (`gui/`):
  - The watcher's changes are read and marked seen under the brains' locks (`Watcher::dirty`, `follow_disk` through
    `locked`); `Watcher::sync` leaves a newly watched folder unread, so a repository found on reload is read again
    under its lock.
  - `Mode::remap` keeps an open dialog on its project when a reload changes the list of brains, and closes it when
    its project is gone.
  - A button's tooltip names its key only on the tabs where the key does the same (`Board::shortcut(When)`).
  - The `#tag` filter reads a tag as `kb search` does (`Task::has_term`).
  - `$VISUAL` set but empty falls back to `$EDITOR`.
  - Fonts (`ui::FONTS`, `gui/fonts/`): IBM Plex Sans and Lilex are embedded and added at start. GPUI takes "IBM Plex
    Sans" for the system font on Linux, where without it no bold or italic showed; `theme::EDITOR_FONT` is Lilex.
  - Keys for every button (`state/keys.rs`, `state/manage.rs`): `N` edits the repository's role (`Board::repo_here`),
    `C` lists the entry's comments to edit (`enter`) or delete (`x`) one (`Mode::Comments`, `CommentPicker`),
    `ctrl+d` discards the editor's changes, `shift+tab` (`KeyCode::BackTab`) goes back a tab or a form field. Manage
    project (`key_manage_project`): `↑` `↓` highlight a repository for `r` `M` `x` `N`; `R` `E` `A` `X` act on the
    project.
  - `Form::tab_to` selects the field's text; saving without a title says so under it (`Form::title_missed`).
  - The board scrolls sideways (`board::draw`, `Scrolls::board`) to the selected card's column instead of laying the
    Done column under the details; a card's question wraps within the card.
  - `Board::tag_colors`: a tag's color is the first brain's that has it in `tags.md`, everywhere and in every scope.
  - `Board::running` orders the top bar's running tasks by when their session started.
  - The layout switch keeps its room on every tab (`invisible` off the board), so the top bar wraps alike.
  - The notes and decisions lists put the brain's label in a column of one width, preview a line without its
    markdown (`markdown::plain`) and count `1 note`; an empty column says how many tasks the search hides; the
    calendar's month names each entry's brain with several shown.
  - Redraws (`ui::IDLE_TICKS`): the tick redraws while a clock runs or a message shows, else once a minute; the
    caret blinks only while typing. A release build with two clocks running took 3.2% of a core, from 5.8%.
- `kb update` and the app's update run `releases/latest/download/install.sh` / `install.ps1` (`cli::update`), not
  `main`'s, which may expect a release that isn't out.
- New tags' colors come from `store::fnv1a`, the same in every build, not std's `DefaultHasher`; colors already in
  `tags.md` are kept.
- `kb list --json` prints on one line. Completions offer every `project` subcommand, `deinit --purge`, `init --repo`
  and `wait --timeout`; `complete projects` only the names `--project` takes (`shop/api`, not `shop` alone), `complete
  ids` open tasks first, then notes, decisions and done tasks.
- Command line (`core/src/cli/`):
  - `Program::misused`: a command-line error is followed by that command's usage lines only, and `kb --help`.
  - Missing text names its command once (`rest_as_text`, `AddArgs::parse`): `reject needs why: TEXT, or - to read it
    from stdin`, `propose needs the decision's title`.
  - `kb list` ends an entry with ` · waiting for an answer`, `· answered`, `· proposed` or `· rejected`
    (`api::text::state_note`), and says `nothing to list` when empty; `kb search` without words is refused.
  - `kb show --json` (`Shown`) adds `repo_linked_from`, the other repositories' entries linking to it; `agents.md`
    documents it with `repo_links`.
  - `kb wait` on a note gives no status. `projects::find` takes a `--project` name in any case when only one has it.
  - `update::agents_working` names tasks as `kb status` does (`shop/api #3`); `remove_repo` tells every way to purge;
    `move_repo` says the repository keeps its role's notes.
  - `model::counted`: `1 session`, `1 task`, `1 entry`, where `session(s)` and `1 entries` were.
  - `fmt_dur` shows less than a minute as `<1m`; `0m` is none.
- Entries sharing an id (`Brain::renumber_shared_ids`, on open): all but one get the next free id and its file name,
  keeping the one under its own name, else the oldest. A sync tool's conflict copy took commands meant for the
  original, and saving it could overwrite the original's file.
- Installers: `install.sh` takes `KANBRAIN_UNINSTALL`, `KANBRAIN_PURGE` and `KANBRAIN_YES` as `install.ps1` does, and
  a cancelled purge exits 0; `install.ps1` no longer overwrites the asked-for `$version` when naming the installed
  one. Purging deletes leftover `.NAME.PID-N.tmp` files in the data folder, `projects/` and `reports/`.
- CI: `cargo publish --dry-run` of both crates, PSScriptAnalyzer on both PowerShell scripts, shellcheck of
  `gui/icons/make.sh`; `release.yml` refuses a tag whose commit has no passing `ci.yml` run.
