kanbrain no longer loses or misses a write when `kb`, agents and the kanban app run at once, never recreates a
deleted repository's brain, and updates from the latest release's installer. An audit of the released code fixed
what could lose data: a file renamed only in case, a byte-order mark, links to an unreadable entry, titles with line
breaks, project cards shared by names that slug alike, and a purge that took files kanbrain didn't make. The kanban
app embeds its fonts, has a key for every button, and redraws only when something on it changes; the command line's
errors and lists say more with less.

- Locks (`core/src/store.rs`, `core/src/projects.rs`, `core/src/cli/mod.rs`):
  - `projects::register`, `unregister` and `rename` hold the central brain's lock from reading `projects.md` to
    writing it: `kb init`s run at once all keep their repository.
  - `run_entries` takes the central brain's lock before the repository's for `kb project rename|repo|move|remove|
    describe|notes`, in the order the app takes them: the two could each hold one and wait for the other.
  - `kb wait` and `kb report` open the brain under its lock, as opening may repair files; `wait` lets go once open.
  - `EntryArgs::read_stdin` reads a `-` argument before the lock, so a command waiting for its input holds up no
    other `kb` nor the app.
  - `Store::lock` records a lock in `HELD` only once taking it can't fail: an error left the thread's later locks
    holding nothing.
- Writes (`store::write_file`): to `.NAME.PID-N.tmp`, a name of the write's own, flushed with `sync_all` before the
  rename. `Store::lock` deletes such files over an hour old in the brain and its folders (`forget_cut_writes`), left
  by a crash.
- A deleted repository stays deleted: `Store::open_named` (`--project`) fails with `… is gone: kb --project NAME
  deinit takes it out`, and `kb update`'s look for agents at work (`update::agents_working`) skips a registered
  folder that's gone, instead of creating its `.brain/`.
- `kb status` (`status_line`) leaves out a brain it can't read (one a newer kanbrain wrote) instead of failing.
- `migrate::format_of` refuses a `format` file saying `0` instead of panicking.
- Temporary brains (`forget_gone_temp_brains`): each lock file in `<tmp>/kanbrain-cache/locks/` names its brain on
  its first line; once that brain is gone, its lock and backups are deleted as another is locked.
- Kanban app (`gui/`):
  - The watcher's changes are read and marked seen under the brains' locks (`Watcher::dirty`, `follow_disk` through
    `locked`); `Watcher::sync` leaves a newly watched folder unread, so a repository found on reload is read again
    under its lock.
  - `Mode::remap` keeps an open dialog on its project when a reload changes the list of brains, and closes it when
    its project is gone.
  - A button's tooltip names its key only on the tabs where the key does the same (`Board::shortcut(When)`).
  - The `#tag` filter reads a tag as `kb search` does (`Task::has_term`).
  - `$VISUAL` set but empty falls back to `$EDITOR`.
  - Fonts (`ui::FONTS`, `gui/fonts/`): IBM Plex Sans and Lilex are embedded and added at start. GPUI takes "IBM Plex
    Sans" for the system font on Linux, where without it no bold or italic showed; `theme::EDITOR_FONT` is Lilex.
  - Keys for every button (`state/keys.rs`, `state/manage.rs`): `N` edits the repository's role (`Board::repo_here`),
    `C` lists the entry's comments to edit (`enter`) or delete (`x`) one (`Mode::Comments`, `CommentPicker`),
    `ctrl+d` discards the editor's changes, `shift+tab` (`KeyCode::BackTab`) goes back a tab or a form field. Manage
    project (`key_manage_project`): `↑` `↓` highlight a repository for `r` `M` `x` `N`; `R` `E` `A` `X` act on the
    project.
  - `Form::tab_to` selects the field's text; saving without a title says so under it (`Form::title_missed`).
  - The board scrolls sideways (`board::draw`, `Scrolls::board`) to the selected card's column instead of laying the
    Done column under the details, again on the next frame once the details have opened (`BrainView::drawer_shown`,
    `on_next_frame`). A card's question wraps within the card; a long title or question is cut at a word's end
    (`text::truncate_words`, `TITLE_CHARS` 90, `QUESTION_CHARS` 110) instead of by GPUI's line clamp, mid-word.
  - Manage project: its editors (`N`, `E`) and adding a repository from it (`AddProject::back`, `Request::Folder`
    with the repository it's added from; the name dialog is then "Add a repository to PROJECT") go back to it, on the
    repository it was on; its body, up to 600 px, scrolls to the highlighted repository (`Scrolls::manage_project`),
    and back to its top on the first, with the keys' line below it, always in view. The rename dialog's link example
    names the repository.
  - The status bar shows messages without the command line's backticks (`Board::notify`). An editor whose text is
    back to what it was is unchanged (`Board::changed`): no `•` in its title, Close rather than Save, nothing saved.
    Answering an agent says "answer sent"; a comment typed and taken back says nothing. A move's message names the
    repository (`shop/api #1`) with several brains shown.
  - Manage project stays open after one of several repositories is taken out; the remove dialog speaks of the one
    repository or the several, and of the project's card only when it goes. The board's list view puts the brain's
    label in a column of one width, as the notes and decisions lists do.
  - A comment of blanks says it was empty, one typed and taken back says nothing; a shown project taken out from the
    command line falls back to All; a comment's heading wraps so its Edit and Delete stay in the details; the New
    button keeps the width of its longest label (`NEW_LONGEST`) on every tab; the bar's project line is plain text;
    the link picker's highlight follows the entry it links; moves, deletes and verdicts name the entry as
    `shop/api #3` with several brains shown (`Board::entry_name`); `u` says "redone" when it redoes; Unlink and
    delete tasks says what it deleted; the remove dialog leaves out links and cards that aren't there.
  - A project renamed from Manage project stays shown; a new task the form puts in Doing while one of yours runs
    stays in To do and says why; saving the title and tags says so; `C` without comments says how to add one; a
    scrolled list says how many rows are above (`↑ 2 above`); the delete dialog and the editor name the entry's
    repository with several brains shown.
  - Ghost buttons (`widgets::Kind::Ghost`) have a `BORDER` outline, so they read as buttons rather than text.
    `Board::same_repos`, which every reload of changed brains now asks, compares labels too: a repository renamed
    with `kb project repo` shows under its new name. A project shown and renamed from the command line stays shown
    under its new name (`Board::reload`). Saving the form unchanged writes and says nothing. Clamped titles end with
    an ellipsis (`text_ellipsis`) in the calendar's week and on a dragged card; a week's move wraps in its column.
    A running row of the list view has its stripe over it, not as a border, so its columns line up. The move dialog
    names the entry's repository, as do the edit form and the comments list.
  - A note or decision of headings alone previews its first heading. The delete dialogs say what will be removed.
    A calendar day of several sessions spans from the first (`calendar::summary`), beside their total.
  - `Board::tag_colors`: a tag's color is the first brain's that has it in `tags.md`, everywhere and in every scope.
  - `Board::running` orders the top bar's running tasks by when their session started.
  - The layout switch keeps its room on every tab (`invisible` off the board), so the top bar wraps alike.
  - The notes and decisions lists put the brain's label in a column of one width, preview a line without its
    markdown (`markdown::plain`) and count `1 note`; an empty column says how many tasks the search hides; the
    calendar's month names each entry's brain with several shown.
  - Redraws (`ui::IDLE_TICKS`): the tick redraws while a clock runs or a message shows, else once a minute; the
    caret blinks only while typing. A release build with two clocks running took 3.2% of a core, from 5.8%.
- `kb update` and the app's update run `releases/latest/download/install.sh` / `install.ps1` (`cli::update`), not
  `main`'s, which may expect a release that isn't out.
- New tags' colors come from `store::fnv1a`, the same in every build, not std's `DefaultHasher`; colors already in
  `tags.md` are kept.
- `kb list --json` prints on one line. Completions offer every `project` subcommand, `deinit --purge`, `init --repo`
  and `wait --timeout`; `complete projects` only the names `--project` takes (`shop/api`, not `shop` alone), `complete
  ids` open tasks first, then every other entry, each part newest first.
- Command line (`core/src/cli/`):
  - `Program::misused`: a command-line error is followed by that command's usage lines only, and `kb --help`.
    `kb COMMAND --help`, `kb help COMMAND` (`Program::usage_of`) and `kb help` print the usage.
  - `init_all` says `N repositories already had this version's instructions`, with "more" only after others listed.
  - Missing text names its command once (`rest_as_text`, `AddArgs::parse`): `reject needs why: TEXT, or - to read it
    from stdin`, `propose needs the decision's title`.
  - `kb list` ends an entry with ` · waiting for an answer`, `· answered`, `· proposed` or `· rejected`
    (`api::text::state_note`), and says `nothing to list` when empty; `kb search` without words is refused.
  - `kb show --json` (`Shown`) adds `repo_linked_from`, the other repositories' entries linking to it; `agents.md`
    documents it with `repo_links`.
  - `kb wait` on a note gives no status. `projects::find` takes a `--project` name in any case when only one has it,
    says ``project `shop` has several repositories: name one, shop/api, shop/web`` for a project's bare name,
    and `Store::open_named` and `deinit_dir` take `central` in any case unless a project has the name.
  - `first_id`: `` `abc` isn't an entry id `` without the parser's words; `show`'s usage after its error is its own.
  - `kb list` opens the brain as the entry commands do (`Brain::open_in`, under its lock), so its ids are theirs.
  - `update::agents_working` names tasks as `kb status` does (`shop/api #3`); `remove_repo` tells every way to purge;
    `move_repo` starts with ``moved web from project `shop` to `store` ``, naming the repository as it was there, keeps a name of the repository's own
    (`kb project repo`) unless the project it joins has one, removes its old project's card when it was the last, and
    says when it keeps role notes written for its old project; its old project's description, when it was the last
    repository, goes to the new one if that has none, and is said to be dropped if it has one. `remove_project` leaves out the "keeps its card" lines of all
    but its last repository. A merged report names tasks `api #3` (`Slot::label`), as the app does.
  - A status move or a verdict that changes nothing says so on stderr (`#3 was already done: nothing changed`).
  - `model::counted`: `1 session`, `1 task`, `1 entry`, where `session(s)` and `1 entries` were.
  - `fmt_dur` and `fmt_age` show less than a minute as `<1m`; `0m` is a duration of none, and an age is never `0m`.
- Entries sharing an id (`Brain::renumber_shared_ids`, on open): all but one get the next free id and its file name,
  keeping the one under its own name, else the oldest. A sync tool's conflict copy took commands meant for the
  original, and saving it could overwrite the original's file.
- Installers: `install.sh` takes `KANBRAIN_UNINSTALL`, `KANBRAIN_PURGE` and `KANBRAIN_YES` as `install.ps1` does, and
  a cancelled purge exits 0; `install.ps1` no longer overwrites the asked-for `$version` when naming the installed
  one. Purging deletes leftover `.NAME.PID-N.tmp` files in the data folder, `projects/` and `reports/`.
- Data (`core/src/store.rs`, `model/markdown.rs`, `brain/`):
  - `Store::save` keeps a file whose name differs from the entry's only in case (`same_ignoring_case`): writing
    the lowercase name and removing the old one deleted the only copy on macOS and Windows.
  - `store::read_text` drops a leading byte-order mark from entries, `last-id`, `tags.md`, `format`, `projects.md`
    and cards: `# title` read as `untitled` and was saved so.
  - `drop_dangling_links` keeps links to ids whose file is there but doesn't parse (`Store::file_ids`);
    `drop_dangling_repo_links` also those, and links to ids above the repository's `last-id` (a branch from before).
  - `model::one_line` joins a title's line breaks with spaces in `add`, `update` and `propose`;
    `Task::from_markdown` joins the lines between `# title` and `- id:` that older versions wrote that way.
  - `projects::card_path`: a name that isn't its own slug adds 8 hex digits of `fnv1a` (`my-app-1a2b3c4d.md`);
    a card is read only when titled with its project (`card_owner`), from its pre-0.3.6 place too (`legacy_card`),
    and moved there once written; `write_description` moves another project's card out of its way first.
  - Parsing keeps enum names in any case (`named_enum!` `parse`), every `- links:` line, text among the keys
    (`unknown.meta`) and a first line's indentation (`without_blank_ends`).
  - `TagColor::parse` refuses non-ASCII hex (a panic on every open); `take_id` refuses past `u32::MAX`.
  - `Store::at` writes `format` when it makes a brain; `migrate_all` (`init --all`) reports a repository it can't
    migrate and goes on.
- Projects (`core/src/projects.rs`, `cli/init.rs`, `cli/manage.rs`):
  - `init` with another project's name goes through `move_repo` (`init::join` registers); a folder whose path has a
    line break, or whose `.brain/` is the central brain, is refused; one moved by hand gets a line naming its old
    place and `deinit` for it.
  - `repo_name` refuses a name a gone repository of the project keeps; a folder's name becomes one links can hold
    (`repo_name_of_folder`: `My App` is `My-App`), and `init --all` renames older ones.
  - `info` and `init` take the project from the registry over the card; `init --all` fixes a card left on a
    renamed project's old name.
  - `check_name` refuses `central` in any case; `project rename OLD NEW` is refused with the command to use.
  - `move_repo` names the repository as it was where it left, and says when its project's description is dropped.
- Agents (`core/src/cli/`, `brain/actions.rs`, `model/`):
  - `Comment::answer` (`answer` in the header): `resolve` marks the verdict it adds to a task asking about that
    decision (`#ID` in its question), which `Task::asked` takes as the answer, an agent's included.
  - `stdin_text` refuses an empty stdin for `-`; `typed_links` refuses a word that isn't a link; `list --tag` takes
    one tag; `say_skipped` names unreadable entry files on stderr.
  - `cli::options`: `--` ends a text's options (`--project`, `--json`, `add`'s), the first one only; `-h`/`--help` count right after the
    command only.
  - `wait` keeps the question it found waiting (`asked_at`) and prints its answer after a move; a failed read after
    the first is looked again at, and so is one without the entry (`missed`): gone twice in a row, it's deleted.
    `--timeout` refuses a count that overflows.
  - The Stop hook's reminder asks to report only on a task the agent started; `KANBRAIN_AUTHOR` is read in any case,
    empty as unset; `docs/agents.md` says how to answer as a person inside Claude Code.
- Installers and updates:
  - Purge deletes a file only for what it holds (`is_owned`, `Test-Owned`): an entry's `- id:` matching its name,
    `tags.md`'s and `projects.md`'s headers, a number in `last-id` and `format`, a registered project's card, a
    report's header. The data folder is resolved (`pwd -P`) and refused when it is or holds the home folder.
  - Every app is fetched and checked before any is put in place (`fetch_app`, `install_app`); `latest` resolves to
    a tag once; an app that doesn't start is said; a leftover `.new` is removed. The PATH hint quotes the folder;
    the menu entry escapes it (`desktop_quoted`).
  - `kb update` says when it's on the latest release (`up_to_date`), and runs the installer without
    `INSTALLER_CHOICES`; the app's update restarts from its file, not `… (deleted)` (`running_file`).
- Kanban app: `sources::load` takes each brain's lock and leaves out, said, a repository that can't be read; dialog
  titles name the entry's repository (the link picker's too) and carry a `dialog TITLE` selector the window tests
  check.
- Tests: generated entries round-trip, settle after one save and never crash the parser
  (`core/tests/model/markdown.rs`); a failed write leaves no temporary.
- CI: `cargo publish --dry-run` of both crates, PSScriptAnalyzer on every PowerShell script, shellcheck of every
  shell script; `release.yml` refuses a tag whose commit has no passing `ci.yml` and `mutants.yml` run.
  `mutants.yml` (`cargo mutants --in-diff` on each change, exclusions in `.cargo/mutants.toml`, runs queued, not
  cancelled); new `ci.yml` jobs: `upgrade` (`e2e/upgrade.sh`:
  brains every release wrote, opened by this build), `app-smoke` (`e2e/smoke-app.sh`, `.ps1`: the release app
  starts and idles under 3% of a core on Linux, macOS and Windows, its screenshot kept).
