Agents work in parallel: one splitting its work between subagents runs a task per subagent in Doing, beside yours,
while you keep to one at a time. Breaking: starting a second task of yours is refused instead of parking the first.

- Doing (`core/src/brain`): a person runs one task per brain; `Brain::set_status` to `doing` fails with
  `ApiError::DoingFull(id)` while one a person started is there, instead of parking it (`kb start` exits 1, the
  board shows the error). Agents' starts aren't limited. Who runs a task is `Task::started_by`, the author of its
  latest `-> doing` history line; loading parks all but the latest of a person's (`keep_one_person_doing`), never
  an agent's. `move_to` needs that room in the target brain. `Brain::running` yields every running task;
  `Brain::person_doing`; `Brain::park_people_running` (Park & quit) leaves agents' tasks running.
- API: `change_status` returns `Result<()>` (no `· parked #N` line); `Report::merge` takes `&ReportView`;
  `Slot::project` and `Slot::label`; `model::covered`, `model::worked`, `Session::span`.
- Agents' section (`init`): to split work between subagents, the agent `add --start`s a task per part that changes
  the repository, then comments its result and finishes it; never parks, finishes or moves a task it didn't start.
  The `Stop` hook reminds it of each task it started without commenting since.
- Write lock (`Store::lock`, crate `fs4`): every `kb` entry command but `wait`, and the kanban app around each
  input, hold the brain's lock from reading to writing, in `<cache>/kanbrain/locks/<FNV-1a of the path>.lock`.
  Parallel commands no longer overwrite each other's changes or take the same id.
- Time by the clock (`model::covered`): report totals, column totals, tag rows, calendar days, merged reports and
  calendars, the app's Today and the project's week count time tasks ran at once once; task rows keep their own.
- Kanban app: running tasks in cyan when a person started them (`theme::running_color`), green when an agent did;
  "What's next?" asks once your task stops, whatever agents run there.
- e2e: scenarios `full` (the user's task running beside the agent's) and `parallel` (three subagents, three tasks).
