The kanban app's keys, command palette and right-click menu come from one table; the palette offers only what works
now; a proposal is decided from the task waiting on it, with or without a comment; closing a task's details no
longer opens a new task. The command line and the data are unchanged.

- Actions (`gui/src/state/keys.rs`): `ACTIONS: &[Action]`, each with its key (`shown` for the palette), `Tabs`
  (`Every`, `Entries`, `Board`, `Lists`, `Report`, `Calendar`), `When` it's offered, palette text (`does`), menu
  `label`, `danger`, `run`. `Board::key_normal` runs the first action of the tab matching the key (the old
  per-tab matches in `input.rs` are gone); `commands` (palette) and `menu_items` filter by `When::holds`;
  `label_of` names the details' buttons. Tests: no key runs two functions on one tab; every key is in
  `docs/keybindings.md` on its tabs.
- Palette (`state/palette.rs`, `ui/dialogs/pickers.rs`): sections `Section::Entry`, `Tab`, `Everywhere`, the first
  row of each named; `esc` rows (`When::Drawer`, `Searched`); "Move up and down the list" on notes and decisions.
- New keys: `E` (`Board::edit_project_description`, the project bar's Edit), `D` (`Board::open_proposed`), `Y`
  (`Board::accept_with_comment`, `Target::Accept`, `brain::resolve(Accepted, text)`). `y`, `Y`, `j` act on
  `Board::decision_for`: the selected decision, or the first one the selected task waits on (`proposed_for`); such
  a task offers no plain Answer (`When::Asks`). `Board::project_here` is the project `I`, `E` and the palette use.
- Editor (`ui/dialogs/editor.rs`, `Board::save_edit`): unmodified, its one button is Close; modified, Answer / Add
  comment / Reject / Accept / Save by target. A blank comment, answer, rejection or accepting comment isn't saved,
  and the status bar says so ("nothing answered: the question still waits").
- Details (`ui/drawer.rs`): buttons through `ui::entry_action` and `Board::run_on_entry`, which act on the entry on
  any tab (on the calendar they pressed its own `d`, `m`, `t`); labels from `label_of`.
- Columns and list sections: the + beside the count, no longer at the header's end, where closing the details put it
  under the pointer. The top bar's Project info is Manage project (`Kind::Secondary`).
