The kanban app opens the entry a `#12`, `REPO#12` or `REPO #12` written in a text names; the agent section `kb init`
writes asks agents to always base their work on official documentation, link the page any text rests on, and name
entries that way. No data format change: nothing to migrate.

- `kanbrain-core` / `kb`:
  - `cli::init` (`SECTION`): a bullet to always base what the agent does and writes on the official documentation of
    the language, library, tool or API, at the version the repository pins (its manifest or lockfile), never on
    memory or posts elsewhere; whatever it writes that rests on it (a description, decision, note or comment) links
    the page, and with no official documentation it says so. The links bullet names entries plainly, `#12`, or
    `REPO#12` in another repository of the project, which the board makes links. `init --all`, run by the installers
    and `kb update`, rewrites it in every registered repository.
- Kanban app (`gui/`):
  - `ui::markdown`: `references` finds `#12` and `REPO#12` in prose (a repository name of letters, digits, `-`, `_`,
    `.`, starting with neither `-` nor `.`; none after `/`, `@`, `#` or `&`, nor in a word with `://`, split at any
    whitespace, non-ASCII too); `repo_before` reads `api #12` and `shop/api #12`, as the app and kb's reports name
    entries; `Builder::prose` draws those whose entry exists as links (`LinkTarget::Entry`), skipping ones after `PR`,
    `issue`, `MR` or a pull or merge `request`, plurals too, across a line break, a bracket or the span before
    (`after_a_number_word`); code spans, code blocks and a link's text stay as markdown draws them. Text events are
    merged (`TextMergeStream`), so `#3_` reads as one word. `render` takes the resolver: `written_in(board, src)` for
    an entry's description, comments and question and a repository's role, `written_for_project(board, src)` (only
    `REPO#12`) for a project's description.
  - `state::sources`: `Board::resolve(src, repo, id)`, the entry a reference names: in the brain at `src`, or in the
    repository `repo` (`api`, or `shop/api` only in its own project `shop`) of its project; `None` when it isn't
    there.
  - `state`: `Board::follow(key)` opens it in the drawer on its tab (`open_entry`), leaving Manage project.
- Tests: `e2e/agent.sh`'s `answered` scenario also accepts the task parked again with a question the agent couldn't
  check (the rule since 0.6.4).
- Docs: `docs/agents.md` (the section, which a test keeps word for word, and its size, about 1,200 tokens),
  `docs/tasks-and-tags.md` (references), `docs/development.md`, `README.md`.
