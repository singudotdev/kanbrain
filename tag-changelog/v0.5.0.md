`kb tag ID +TAG -TAG` and `kb rename ID TITLE` change an entry's tags and title from the shell, as the kanban app's form
does. The app's form saves only what was changed in it, so a `kb rename`, `kb tag` or `kb link` made while it was open
isn't undone. Fish completes by the command word, and a lone carriage return in a title is a line break, as markdown
reads it. Breaking for `kanbrain-core`'s Rust API only (the command line's types are `#[non_exhaustive]`); `kb`, the
app and the data are unchanged, and nothing needs migrating by hand.

- Command line (`core/src/cli/`):
  - `kb tag ID +TAG|-TAG…` (`EntryCommand::Tag`, `entries::tag_changes`, `entries::retag`): each change in order, a
    tag added after the entry's others unless it has it, removed if it has it, through `Brain::update` (tag colors
    included). A word may name several (`+ui,#bug`, `text::parse_tags`); `--` (`unexpected argument`), an option, a
    word without a sign and a sign naming no tag are refused; tags already so write nothing and say
    `#ID's tags were already so: nothing changed` on stderr. `--json` prints the entry.
  - `kb rename ID TITLE…` (`EntryCommand::Rename`, `entries::new_title`, `entries::retitle`): the words joined, on one
    line (`model::one_line`), the file renamed after it by `Store::save`; `--` before a title starting with `--`; a
    blank title refused; the same title writes nothing and says `#ID already had that title: nothing changed`.
    `--json` prints the entry.
  - Completions (`completions.rs`): `tag` completes the id, then `+TAG`/`-TAG` from the brain's tags, in bash (zsh
    through it) and fish; `rename` its id (`BY_ID`). Fish goes by the command, the first word after `kb` that isn't an
    option (`__kb_words`, `__kb_using`, in place of `__fish_seen_subcommand_from` / `__fish_use_subcommand`), so
    `kb project rename `, `kb list todo ` and `kb add … show ` no longer offer ids; `kb report ` offers the periods,
    apart from `--save`'s value.
  - The agents' section (`init::SECTION`, `docs/agents.md`) names `rename ID TITLE` and `tag ID +TAG -TAG`;
    `kb update` brings it to every project (`init --all`). `USAGE`, `--json`'s list, `docs/cli.md` and the READMEs
    list both.
  - `#[non_exhaustive]`: `cli::Command`, `cli::EntryCommand`, `cli::ProjectChange`, `cli::ProjectPart`,
    `cli::TagChange` and `cli::Text` and each of their variants, `cli::EntryArgs`, `cli::AddArgs`, `cli::ListArgs`,
    `cli::ReportArgs` (`docs/decisions/0001-kanbrain-core-follows-cargo-semver.md`: a release's number follows the
    stricter of `kb`'s surface and `cargo semver-checks -p kanbrain-core`).
- Titles and project names (`core/src/`): `model::one_line` splits on `\r` as well as `\n`; `markdown.rs` reads a
  title's `# ` line and its continued lines through it, so a lone `\r` an older version kept in a file's title is a
  space.
  `projects::check_name` refuses a `\r`; `init::rename_unreachable_projects` makes it a `-` in a name an older version
  registered (it panicked: `more names than projects`), as `kb init --all` runs it.
- Kanban app (`gui/`):
  - `Form::opened` (`mode::Opened`: title, tags, related entries as the form opened) and `form::merged`: saving an
    edit writes a field only if it differs from `opened`; an edited list keeps what was added elsewhere meanwhile and
    drops what was taken out, an edited title replaces the entry's. `Mode::remap` remaps `opened.links` with the
    form's when the list of brains changes.
  - `LineInput::insert`: `\r\n` and a lone `\r` become a space, as `\n` does (a lone `\r` was dropped, joining words).
- Tests: `cli/tests/kb.rs` runs bash on `kb completions bash` (`bash_completes`, Unix) for `tag`; `tag` and `rename`
  end to end; `gui/tests/state.rs` saves untouched and edited forms over `kb`'s changes, and across a change of the
  list of brains; `core/tests/cli/init.rs` renames a registered `shop\rapi`.
