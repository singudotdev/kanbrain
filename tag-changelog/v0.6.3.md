PowerShell completion for `kb`; the kanban app selects shown text with the mouse, has scrollbars, a wheel per axis
and no bar of running tasks; Claude Code hooks recognized by a plain path to `kb`, without doubling one that only looks
like kanbrain's; `kb init --all` / `kb update` leave a repository a newer kanbrain wrote untouched; the app fails
saying why instead of hanging or exiting 0; Windows paths, file locks and CRLF files handled. No data format change:
nothing to migrate.

- `kanbrain-core` / `kb`:
  - `kb completions powershell` (`cli::completions`): commands, ids with their titles as tooltips, tags, projects;
    words PowerShell reads otherwise (`$`, quotes incl. `‘ ’ ‚ ‛ “ ” „`, brackets, `* ?`, a leading `– — ―`) in single
    quotes, `'` doubled.
  - Hooks (`cli::claude`): `kanbrains` takes bare `kb hook X` / `kb context`, or `<path> hook X` with the path's last
    component `kb` or `kb.exe`: unquoted `[alphanumeric _ . / : -]` and a leading `~/` (bash), quoted adds space and
    `( )`; `\` only in a Windows-shaped path (`X:\`, `\\`), and under bash only in `'…'`; `& ` required under
    `"shell": "powershell"`; the exec form (`command` + `args`); only `"type": "command"`. `look_alikes` (`kb`
    followed by the hook's words anywhere) gets no copy beside it; `init` and `deinit` say so (`Edited`).
    `remove_hooks` takes only kanbrain's handlers out of a matcher group, dropping the group only when emptied.
  - `migrate::{too_new, refuse_too_new}`, `manage::refuse_too_new`: `init_all` skips a repository whose brain a newer
    kanbrain wrote, and one whose rename would touch such a sibling (`… keeps the name … until kb update`), carrying
    on; `init`, `rename_repo`, `move_repo`, `remove_repo` refuse before any write; `rename_project` renames such a
    repository in the registry only.
  - `projects::{simplified, canonical}`: Windows registry paths without `\\?\` unless the plain path names something
    else (trailing dot or space, device names, over `MAX_PATH`); a non-Unicode path refused at `init`.
  - `store::{rename, remove_file}` retry on Windows while the file is busy (`BUSY_DELAYS`, 10–640 ms, ~1.3 s in all).
  - `KANBRAIN_DIR` empty = unset; relative (incl. `\todo`, `D:todo`) refused; `~…` said to be shell-only.
  - `init` / `deinit` keep a CRLF `CLAUDE.md` / `AGENTS.md` CRLF; an older mixed section mended; a BOM-only file
    removed.
  - `kb update`'s PowerShell command quotes the install folder in `'…'`; `kanbrain update` names `kanbrain` and gives
    `cargo install --locked --git … --tag vX.Y.Z kanbrain-app` (no `--tag` when GitHub didn't answer).
  - `kb report --tag a,b` refused as `list` does.
  - API, additive: `model::Comment::first_line`, `Task::{doing_by, waits_for_answer}`; `store::Store::load_entries`,
    `Skipped`, `SkipReason`; `cli::{Step, StepKind}`, `cli::{init, rename_project, rename_repo, move_repo,
    remove_repo, remove_project}_steps`; `cli::update::{update_program, cargo_update_command}`.
  - Deprecated since 0.6.3: `Brain::{change_status, comment, describe}`, `cli::update::update`, `Store::load`,
    `cli::{init, rename_project, rename_repo, move_repo, remove_repo, remove_project}`.
- Kanban app (`gui/`):
  - `ui::shown`, `ui::pointer`: text shown is selectable (drag, double-click word, triple-click paragraph,
    `shift`+click), copied with `ctrl+c` / `cmd+c` and the Linux primary selection; not on cards; nothing copied from
    under a dialog.
  - `ui::scrollbar`, `board::each_axis`: a scrollbar per overflowing column and under the board; the vertical wheel
    scrolls the column, a horizontal wheel or `shift`+wheel the board.
  - `ui::topbar`: `running_bar` removed; `today()` (today's total, Park & quit only while a task of yours runs,
    `Board::any_mine_running`) ends the projects row; an empty Doing under one project points to All.
  - The form's tags as colored chips with ×.
  - `ui::startup`: an error before the board opens shows in a window titled `kanbrain couldn't open` (Copy, Close),
    exit 1; a board window that can't open does the same. `ui::display` (Linux, FreeBSD): no display, a
    `WAYLAND_DISPLAY` nothing answers at, or a local `DISPLAY` with no X server exits 1 on stderr; `ui::application`
    turns GPUI's connect panics into exit 1.
  - What a read found stays beside the action's message for the whole key or click.
  - Refactors from the post-v0.6.2 audit: `Edit::settle`, `Board::comment_moved`, status-bar `Message` parts with
    `Changed`, `state/mode/` and `tests/state/` split.
- CI and scripts: clippy and `cargo doc` on macOS and Windows; `e2e/smoke-app.sh` runs the app without a display and
  with dead ones; `release.yml`'s actions pinned by SHA; `deny.toml` accepts gpui's zbus 6 crates.
